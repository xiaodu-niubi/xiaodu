# 第13课：编排智能体（Orchestrator）—— 智能体世界的"总调度"

> 🎯 **本课目标**：实现OrchestratorAgent，让它能分析用户意图并决定交给哪个专家处理。

---

## 13.1 编排智能体的角色

在多智能体系统中，Orchestrator就像一个**公司的前台/调度经理**：

```
你走进公司（发起请求）
    ↓
前台（Orchestrator）问你：需要什么帮助？
    ↓
    "我要问产品问题" → 带你去产品部门（RAG Agent）
    "我要算个数"     → 带你去技术部（Tool Agent）
    "我要搜最新消息" → 给你联网（Web Agent）
    "上次我们聊过啥" → 帮你查记录（Memory Agent）
    "就随便聊聊"     → 直接跟你聊（Fallback / 通用LLM）
```

它自己不干活，只负责**判断该派谁去干**。

---

## 13.2 Orchestrator的工作方式

Orchestrator本身也是一个智能体（继承BaseAgent），但它有特殊的system_prompt，告诉LLM：

> "你的任务是分析用户意图，输出一个JSON格式的路由决策，不要回答问题本身。"

```
输入："公司提供哪些产品？"
  ↓ 调用LLM
输出：{
  "next_agent": "rag_agent",
  "reasoning": "用户询问公司产品信息，需要查知识库",
  "sub_message": "公司产品列表"
}
```

## 13.3 写代码：`src/agents/orchestrator.py`

```python
"""编排智能体 - 总调度器，负责分析用户意图并将任务路由到专用智能体

单一职责：分析用户意图，委派给正确的智能体。
不执行工具调用，不检索知识。
"""
from src.agents.base_agent import BaseAgent

# ── 编排智能体的系统提示（核心！）──
ORCHESTRATOR_PROMPT = """你是多智能体系统的编排智能体。你唯一的职责是分析用户请求并将其路由到合适的专用智能体。

## 可路由的智能体：
1. **rag_agent（知识检索智能体）** - 用于需要从文档、手册、政策、FAQ、公司信息中检索知识的问题
2. **tool_agent（工具执行智能体）** - 用于计算、代码执行、单位转换、文件操作、时间查询
3. **web_agent（网络搜索智能体）** - 用于搜索网页、获取URL、查找最新信息
4. **memory_agent（记忆智能体）** - 用于关于对话历史、用户偏好、历史上下文的问题

## 决策规则：
- 用户询问公司信息、产品详情、政策、技术规格或FAQ → **rag_agent**
- 用户需要纯数学计算、单位转换、时间查询、运行已有代码 → **tool_agent**
- 用户需要实时/网络信息 → **web_agent**
- 用户询问之前的对话或偏好 → **memory_agent**
- 用户要求生成/编写代码、写脚本、写程序等创意性编程任务 → **next_agent 设为 null**（走通用LLM直接生成）
- 简单问候、闲聊、常识问题 → **next_agent 设为 null**

## 重要区分：
- "帮我运行这段python代码" → tool_agent（执行已有代码）
- "帮我写一个贪吃蛇游戏" → null（代码生成，走通用模型）
- "计算 123*456" → tool_agent（纯计算）
- "用python写一个处理excel的脚本" → null（代码生成）
- "今天天气怎么样" → web_agent（需要实时信息）
- "你好" → null（闲聊）
- "1+1等于几" → tool_agent（数学计算）

## 输出格式：
仅以 JSON 格式回复路由决策，不要输出任何其他内容：
```json
{
  "next_agent": "<rag_agent | tool_agent | web_agent | memory_agent | null>",
  "reasoning": "<为什么这样路由的简要原因>",
  "sub_message": "<发送给智能体的优化后的查询>",
  "requires_multi_agent": false
}
```

如果不需要路由（next_agent为null），sub_message设为原始用户消息。
对于无需专家的简单问候、闲聊、代码生成，将 next_agent 设为 null。"""


class OrchestratorAgent(BaseAgent):
    """编排智能体 - 分析并路由请求"""

    name = "orchestrator"
    system_prompt = ORCHESTRATOR_PROMPT
    tools = []          # 编排智能体不需要工具
    max_iterations = 3  # 最多3轮（一般1轮就够）

    def route(self, user_message: str, history: list[dict] = None) -> dict:
        """分析并路由请求，返回路由决策
        
        返回格式：
        {
            "next_agent": "rag_agent",         # 目标智能体名称（或null）
            "reasoning": "用户询问公司信息",     # 路由理由
            "sub_message": "公司产品列表",      # 优化后的查询
            "requires_multi_agent": false       # 是否需要多智能体协作
        }
        """
        import json
        import re

        # 调用父类的run方法（触发ReAct循环，但这里通常不需要工具）
        result = self.run(user_message, history)

        # 从LLM的回复中提取JSON
        content = result.get("content", "")
        try:
            # 尝试直接解析
            decision = json.loads(content)
        except json.JSONDecodeError:
            # LLM可能把JSON放在markdown代码块里，用正则提取
            match = re.search(r'```(?:json)?\s*(\{.*?\})\s*```', content, re.DOTALL)
            if match:
                try:
                    decision = json.loads(match.group(1))
                except json.JSONDecodeError:
                    decision = {"next_agent": None, "reasoning": "解析失败", "sub_message": user_message}
            else:
                decision = {"next_agent": None, "reasoning": "解析失败", "sub_message": user_message}

        return decision
```

## 13.4 路由决策详解

| 用户输入 | next_agent | 原因 |
|---------|------------|------|
| "公司有什么产品？" | `rag_agent` | 需要查知识库 |
| "退款政策是什么？" | `rag_agent` | 需要查政策文档 |
| "计算 123 × 456" | `tool_agent` | 纯数学计算 |
| "帮我写一个贪吃蛇" | `null` | 代码生成，走通用LLM |
| "今天天气怎么样" | `web_agent` | 需要实时信息 |
| "刚才我们聊了什么" | `memory_agent` | 查对话历史 |
| "你好" | `null` | 闲聊，走通用LLM |

---

## 13.5 为什么代码生成不走tool_agent？

这是个重要的设计决策：
- **tool_agent**被限制为只能执行工具，受限于简单的提示词
- **代码生成**（如写一个游戏）需要的是创意，不是工具执行
- 所以代码生成直接走**fallback节点**（通用大模型），不受工具智能体的角色限制

## 13.7 JSON解析的鲁棒处理

注意 `route()` 方法中对JSON解析的处理：

```python
try:
    decision = json.loads(content)    # 第1次尝试：直接解析
except json.JSONDecodeError:
    match = re.search(r'```(?:json)?\s*(\{.*?\})\s*```', content, re.DOTALL)
    if match:
        decision = json.loads(match.group(1))  # 第2次尝试：从```json```块中提取
    else:
        decision = {"next_agent": None, ...}  # 兜底：走通用LLM
```

这是因为大模型有时候不听话，会在JSON外面加额外的文字或markdown格式。做好容错处理很重要。
